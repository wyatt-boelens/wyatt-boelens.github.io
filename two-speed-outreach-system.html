CASE STUDY — SYSTEMS DESIGN

The Two-Speed Outreach System

A campaign-architecture upgrade to an existing outreach tool — deliberately built with two speeds instead of one, so more sophistication didn't come at the cost of the tool getting used less often.

Genericized reconstruction for portfolio purposes. The architecture — the mode gate, the two-layer classification, the dual-matching guardrail, the variant-rotation fix — is real and mine. The company and brand names below are fictional.

The problem

An existing single-touch outreach tool worked well but was thin: one opener per prospect, one taxonomy, no sequencing logic. The obvious move was to make it deeper — multi-touch campaigns, forensic research, cadence planning, competitor-aware social proof. The less obvious risk: if every batch now pays the overhead of a full campaign build, the tool stops being fast enough for the routine, everyday case — and a sophisticated system that quietly gets used less isn't actually an upgrade.

The fix wasn't choosing depth over speed. It was making the choice explicit, every time, instead of letting the more complex path become the only path by default.

The architecture
01
The fast path is a first-class mode, not a fallback

Every batch starts with the same question: quick pass or full campaign. Without that gate, the richer system becomes the only system — and depth that isn't chosen deliberately just turns into overhead on the routine batches that make up most of the actual workload.

02
Function and authority are separate axes, not one taxonomy

Function — the existing, tuned category system — determines what a message is about. Authority (decision maker, influencer, end user) determines how it's delivered: tone, cadence, channel. Collapsing them into one scheme would mean rebuilding a proven content library from scratch every time the segmentation lens changes.

03
Two matching mechanisms, two different jobs, one guardrail

Complementary brand matching answers "why would this make sense for you." Competitor social proof answers "why now." The second carries real relationship risk if handled carelessly, so it defaults to soft, vertical-level framing and only names a specific reference on explicit confirmation that the relationship is safe to disclose.

04
Repetition gets designed out, not caught after the fact

An early test run surfaced a real failure mode: two contacts at the same account, same role, landing in the same bucket and receiving word-for-word identical copy. The fix lives in two places — message-level variant rotation whenever a batch repeats a persona at the same touch, and timing-level staggering in the cadence layer, so the same two contacts never receive the same touch on the same day either.

05
Cadence comes from a playbook, not fresh judgment every run

A small set of proven patterns, selected by contact count and account size rather than researched from scratch each time — and every pattern is scoped to what one person can actually execute, not a theoretical team-scale motion nobody's going to run.

Extend or rebuild — the trade-off, scored before committing

Before building this, the honest question was whether it was actually an upgrade or just a more impressive-looking trade. Scored side by side against the tool it replaced:

Why this matters

Most tool rebuilds get evaluated on what the new version can do. Fewer get evaluated on what happens to the thing the new version might quietly stop being used for. Scoring that trade-off before building, not after, is what kept this from becoming a more sophisticated system that gets opened less often.

Where this stops

This system generates messaging, sequencing, and cadence recommendations — it doesn't send anything, and it can't confirm what actually went out. The duplicate-check layer tracks what's been generated, not what's been delivered or replied to; verifying real send status is a separate system's job. The mode-gate, exclusion, and disclosure decisions are still deliberately left to a human — the architecture structures those choices, it doesn't make them.
